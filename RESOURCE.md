# Redesign Provider Resource API

## Context

The current resource definition API uses zod schemas and a tRPC-style builder chain (`t.resource.input(z.object({...})).handle({...})`). We want to drop zod in favor of plain TypeScript types and simplify the API. The libraries are evolving — this is the opportunity to get the API right.

Key motivations:
- Zod adds ceremony without value (schemas are never validated at runtime in the handler path)
- TypeScript types can carry semantic meaning (`Secret`, `Output`) that zod can't express naturally
- Builder chains don't look natural with plain TypeScript types
- `Ref` → `Output` / `SecretRef` → `SecretOutput` naming is clearer

## Two distinct functions

There are two separate concepts that need different names:

| Concept | Current | New |
|---------|---------|-----|
| **Definition** — how a resource behaves (handlers) | `t.resource.input(schema).handle({...})` | `defineResource<Input>("name", handlers)` |
| **Constructor** — creates ResourceEntry for configs | `resource(providerName, provider, type, define)` | Generated by `createProvider` internally |

Provider authors use `defineResource`. Users never see it — they use the constructors that `createProvider` generates.

## New API

### Resource definitions (provider authors)

```ts
// packages/std/src/fs/file.ts
import { defineResource } from "@vyft/provider";

interface FileInput {
  source: string;
  encoding?: "utf-8" | "base64";
}

export const file = defineResource<FileInput>("file", {
  async create({ input, ctx }) {
    const raw = await fs.readFile(input.source);
    const content = raw.toString(input.encoding ?? "utf-8");
    const sha256 = crypto.createHash("sha256").update(raw).digest("hex");
    const stat = await fs.stat(input.source);
    return { output: { content, sha256, size: stat.size } };
  },
});
```

```ts
// packages/std/src/process/exec.ts
interface ExecInput {
  command: string[];
  stdin?: string;
  connection?: { host: string; privateKey: Secret };
}

export const exec = defineResource<ExecInput>("exec", {
  async create({ input, ctx }) {
    const { stdout } = await executeCommand(input.command, ...);
    const ref = await ctx.artifacts.write("stdout", stdout);
    return { output: { stdout: ref } };
  },
});
```

- `defineResource<Input>(name, handlers)` — generic function, Input is the TypeScript type
- Output type is **inferred** from the `create` handler's return type
- No zod, no builder chain, no `.handle()` wrapper
- `ctx.artifacts` instead of separate `artifacts` param
- `create` returns `{ output, externalId? }` (same shape as current `CreateResult`)

### createProvider (same as now, but with defineResource results)

```ts
// packages/std/src/index.ts
export default createProvider({
  name: "std",
  context: async () => ({}),
  resources: {
    fs: { file, glob, template },
    crypto: { randomBytes, randomUuid, sshKeyPair },
    process: { exec },
  },
});
```

### User configs (unchanged)

```ts
import { std } from "vyft";
export const readme = std.fs.file("readme", { source: "./README.md" });
```

### Output references

Rename `Ref` → `Output`, `SecretRef` → `SecretOutput`:

```ts
// Accessing another resource's output (deferred value)
const db = service("db", { image: "postgres", port: 5432 });

// db is a ResourceEntry — it has .urn
// createOutput(db.urn, "host") → Output
// createSecretOutput(db.urn, "password") → SecretOutput
```

### Secret type

```ts
// Branded type for resource input interfaces
export type Secret = string & { readonly [SECRET]: true };

// Usage in input types
interface ExecInput {
  command: string[];
  connection?: {
    host: string;
    privateKey: Secret;  // engine encrypts this at rest
  };
}

// At config time, user wraps with secret()
std.process.exec("deploy", {
  command: ["apt-get", "update"],
  connection: { host: "1.2.3.4", privateKey: secret(myKey) },
});
```

### Platform resources

The platform system has three layers: **core contracts**, **runtime constructors**, and **platform providers** (e.g. docker).

#### 1. Core contracts (`packages/core/src/platform.ts`)

Currently uses zod schemas. Replace with plain TS interfaces:

```ts
// packages/core/src/platform.ts
export interface ServerInput { name: string; size: string; }
export interface VolumeInput { size: number; zone: string; }
export interface NetworkInput { cidr: string; }

// Used by createProvider to validate platform providers implement all required resources
export type PlatformResourceName = "server" | "volume" | "network";
```

No runtime validation needed — TypeScript enforces the contracts at build time.

#### 2. Runtime package (`packages/runtime/src/`)

The runtime package has two roles:
- **`schemas.ts`** — defines ServiceInput/VolumeInput/CronJobInput (the full input shapes that handlers receive)
- **`constructors.ts`** — exports `service()`, `volume()`, `cronjob()` constructors that users call in configs
- **`define.ts`** — `defineRuntime()` helper that platform providers use to register their handler implementations

**schemas.ts** — replace zod schemas with plain interfaces:

```ts
// packages/runtime/src/schemas.ts
export interface ServiceInput {
  name: string;
  image?: string;
  path?: string;
  cwd?: string;
  port: number;
  route?: string;
  env?: Record<string, string>;
  command?: string[];
  mounts?: Array<{ source: string; target: string }>;
  health?: { path: string; interval?: string; timeout?: string; retries?: number };
  restart: "always" | "on-failure" | "unless-stopped" | "no";
  expose?: boolean;
}

export interface VolumeInput { name: string; size?: string; }

export interface CronJobInput {
  name: string;
  schedule: string;
  image?: string;
  path?: string;
  cwd?: string;
  command?: string[];
  env?: Record<string, string>;
  mounts?: Array<{ source: string; target: string }>;
  health?: { path: string; interval?: string; timeout?: string; retries?: number };
  restart: "always" | "on-failure" | "unless-stopped" | "no";
}
```

**define.ts** — `defineRuntime` now returns `ResourceDefinition` objects (no schema field):

```ts
// packages/runtime/src/define.ts
import { type Handlers, RESOURCE, type ResourceDefinition } from "@vyft/core";

export interface RuntimeConfig<TCtx> {
  context: () => Promise<TCtx> | TCtx;
  handlers: {
    service: Handlers<ServiceInput, TCtx>;
    volume: Handlers<VolumeInput, TCtx>;
    cronjob: Handlers<CronJobInput, TCtx>;
  };
}

export function defineRuntime<TCtx>(config: RuntimeConfig<TCtx>): ProviderConfig<TCtx> {
  return {
    context: config.context,
    resources: {
      service: { [RESOURCE]: true, name: "service", handlers: config.handlers.service },
      volume: { [RESOURCE]: true, name: "volume", handlers: config.handlers.volume },
      cronjob: { [RESOURCE]: true, name: "cronjob", handlers: config.handlers.cronjob },
    },
  };
}
```

**constructors.ts** — rename `createRef` → `createOutput`:

```ts
// Only change: createRef → createOutput, createSecretRef → createSecretOutput
import { createOutput, ... } from "@vyft/core";
// ...
envWithRefs[`${prefix}_HOST`] = createOutput(ref.urn, "host");
envWithRefs[`${prefix}_PORT`] = createOutput(ref.urn, "port");
envWithRefs[`${prefix}_URL`] = createOutput(ref.urn, "url");
```

The constructors (`service`, `volume`, `cronjob`) keep their current shape — they are hand-written because they have config→input transformation logic (e.g. `service` adds `PORT` env, handles `link`, sets defaults). They use `resource()` from core directly, not `defineResource`.

#### 3. Platform providers (`packages/docker/src/`)

Docker (and future providers) use `defineRuntime` to register handler implementations:

```ts
// packages/docker/src/index.ts
import { defineRuntime } from "@vyft/runtime";
import { serviceHandlers } from "./service.ts";
import { volumeHandlers } from "./volume.ts";
import { cronjobHandlers } from "./cronjob.ts";

export default defineRuntime<DockerContext>({
  context: createDockerContext,
  handlers: {
    service: serviceHandlers,
    volume: volumeHandlers,
    cronjob: cronjobHandlers,
  },
});
```

Handler implementations update to new signatures (ctx.artifacts, `{ output, externalId? }` return):

```ts
// packages/docker/src/service.ts
export const serviceHandlers: Handlers<ServiceInput, DockerContext> = {
  async create({ input, ctx }) {
    const container = await ctx.docker.createContainer(input);
    return {
      externalId: container.id,
      output: { host: "localhost", port: input.port, url: `http://localhost:${input.port}` },
    };
  },
  async delete({ input, ctx }) { ... },
  async diff({ old, new: next }) { return { action: "recreate" }; },
};
```

#### Summary of platform resource flow

```
User config:    service("db", { image: "postgres" })     ← runtime/constructors.ts
                        ↓
Config time:    resource() creates ResourceEntry           ← core/resource.ts
                        ↓
Deploy time:    CLI loads docker provider via defineRuntime ← runtime/define.ts
                swaps lazyProvider with real handlers
                        ↓
Execution:      resolve() calls serviceHandlers.create()   ← core/resolve.ts
```

Nothing changes in this flow — we're just replacing `{ schema, handlers }` with `{ [RESOURCE]: true, name, handlers }` and dropping zod from the input type definitions.

## Type details

### ResourceDefinition (core)

```ts
// Replaces current { schema: z.ZodType, handlers: Handlers }
export const RESOURCE: unique symbol = Symbol("vyft.resource");

export interface ResourceDefinition<TInput = unknown, TCtx = unknown> {
  [RESOURCE]: true;
  name: string;
  handlers: Handlers<TInput, TCtx>;
}
```

Symbol brand for reliable detection in `createProvider` (replaces `"schema" in v` check).

### Handler signatures

```ts
export interface HandlerArgs<TInput, TCtx> {
  input: TInput;
  ctx: TCtx & { artifacts: Artifacts };
}

export interface UpdateArgs<TInput, TCtx> {
  input: TInput;
  old: unknown;
  ctx: TCtx & { artifacts: Artifacts };
}

export interface DiffArgs<TInput> {
  old: TInput;
  new: TInput;
  ctx: { artifacts: Artifacts };
}

export interface CreateResult {
  externalId?: string;
  output: Record<string, unknown>;
}

export interface Handlers<TInput, TCtx> {
  create?(args: HandlerArgs<TInput, TCtx>): Promise<CreateResult>;
  read?(args: HandlerArgs<TInput, TCtx>): Promise<Record<string, unknown>>;
  update?(args: UpdateArgs<TInput, TCtx>): Promise<Record<string, unknown>>;
  delete?(args: HandlerArgs<TInput, TCtx>): Promise<void>;
  diff?(args: DiffArgs<TInput>): Promise<DiffResult>;
}
```

- `create` returns `{ output, externalId? }` — keeps current `CreateResult` shape
- Artifacts merged into ctx via intersection type

### defineResource

```ts
// packages/provider/src/define.ts
export function defineResource<TInput, TCtx = Record<string, never>>(
  name: string,
  handlers: Handlers<TInput, TCtx>,
): ResourceDefinition<TInput, TCtx> {
  return { [RESOURCE]: true, name, handlers };
}
```

That's it. A thin wrapper that attaches the name and brand symbol.

### Output / SecretOutput (renamed from Ref / SecretRef)

```ts
// packages/core/src/output.ts (renamed from ref.ts)
export const OUTPUT: unique symbol = Symbol("vyft.output");

export interface Output {
  [OUTPUT]: true;
  readonly urn: string;
  readonly path: string;
  readonly kind: "output";
}

export interface SecretOutput {
  [OUTPUT]: true;
  [SECRET]: true;
  readonly urn: string;
  readonly path: string;
  readonly kind: "secret";
}

export function createOutput(urn: string, path: string): Output { ... }
export function createSecretOutput(urn: string, path: string): SecretOutput { ... }
export function isOutput(value: unknown): value is Output { ... }
```

The `kind` field acts as a discriminant — TypeScript can distinguish `Output` from `SecretOutput` structurally. No phantom types needed.

## Files to change

### Core (`packages/core/src/`)
- `resource.ts` — update ResourceDefinition (drop schema, add symbol brand), handler arg types (merge artifacts into ctx), keep CreateResult as-is
- `ref.ts` → `output.ts` — rename Ref→Output, SecretRef→SecretOutput, createRef→createOutput, etc. Use `kind` discriminant instead of phantom types.
- `context.ts` — no change (artifacts already on Context, handlers get it via merge)
- `resolve.ts` — merge artifacts into provider ctx
- `plan.ts` — merge artifacts into diff ctx
- `refresh.ts` — merge artifacts into read ctx
- `secret.ts` — add `Secret` branded type (string-only) for use in input interfaces
- `platform.ts` — replace zod schemas with plain TS interfaces
- `envelope.ts` — update references from Ref to Output
- `interpolate.ts` — update references
- `index.ts` — update exports (Output, SecretOutput, createOutput, defineResource re-export)

- `builder.ts` — remove (or gut it; `initProvider` no longer needed)
